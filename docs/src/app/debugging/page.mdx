# Debugging

Use debugging commands to set breakpoints and logpoints in compiled JavaScript, recover paused pages, inspect browser logs and page errors, handle JavaScript dialogs, capture Chrome traces, highlight elements, and open the live DevTools frontend.

## Compiled JavaScript debugger

The debugger operates on JavaScript exactly as Chrome loaded it. It does not require project sources or source maps, so it works with production bundles, Rstack output, and Module Federation containers.

```bash
agent-browser open https://app.example.com
agent-browser debug enable
agent-browser debug scripts --filter assets --json
agent-browser debug source search "checkout" --filter assets --json
```

`debug scripts` returns exact script instance identity, conservative source lineage, and runtime owner evidence. Parent and initiator information is retained as evidence and is never used as identity. A default execution context can contain both Host and Module Federation remote code, so the generic substrate reports its owner as `unknown` until a caller supplies reliable evidence. Persistent probes do not automatically rebind for an unknown or ambiguous owner.

`debug source <script-id>` returns at most 32 MiB in one response. `debug source search` searches daemon-side, returns one-based UTF-16 start and end positions with bounded context, and is limited to 100 matches by default or 1,000 when explicitly requested.

### Breakpoints and compiled locations

```bash
agent-browser debug breakpoint set <script-id> <line> --strict --json
agent-browser debug breakpoint set <script-id> <line> --condition "order.total > 100" --json
agent-browser debug breakpoint list --json
agent-browser debug breakpoint remove <probe-id>
```

Lines and columns are one-based. Columns count UTF-16 code units. Before installation, agent-browser asks Chrome for possible breakpoint locations within the same function.

  <thead>
    <tr><th>Mode</th><th>Behavior</th></tr>
  </thead>
  <tbody>
    <tr><td><code>--strict</code></td><td>Requires a breakable location on the requested line and, when explicitly supplied, the requested column.</td></tr>
    <tr><td><code>--before</code></td><td>Selects the closest earlier point only after Chrome proves that it reaches an anchor in the requested function.</td></tr>
    <tr><td><code>--after</code></td><td>Selects the closest point at or after the request in the same function. This is the default.</td></tr>
    <tr><td><code>--nearest</code></td><td>Chooses the closest verified point and prefers forward when distances tie.</td></tr>
    <tr><td><code>--nearest-forward</code></td><td>Compatibility alias for <code>--after</code>.</td></tr>
    <tr><td><code>--max-lines &lt;n&gt;</code></td><td>Bounds resolution by line distance. The default is 3 and the maximum is 500.</td></tr>
    <tr><td><code>--max-utf16-distance &lt;n&gt;</code></td><td>Bounds resolution by UTF-16 code units. The default is 512 and the maximum is 1,000,000.</td></tr>
  </tbody>
</table>

Conditions and log expressions are syntax checked in the script execution context before a breakpoint is installed. Runtime scope errors remain evaluation evidence and do not create an unrelated pause.

### Pause inspection and recovery

An ordinary command can be waiting for renderer JavaScript that stopped at a breakpoint. Debugger commands use a separate controller, event listener, state lock, and direct CDP path, so another CLI or MCP request can still inspect and resume the page.

```bash
# First shell can remain blocked here
agent-browser eval "startCheckout()"

# Second shell remains responsive
agent-browser debug status --json
agent-browser debug stack --json
agent-browser debug eval "order.id" --frame 0 --json
agent-browser debug step-over
agent-browser debug resume
```

If one page is paused, the selector can be omitted. If multiple pages are paused, select exactly one with `--tab <tN>`, `--session <cdp-session-id>`, or `--pause-id <pause-id>`. Frame evaluation accepts either `--frame <zero-based-index>` or `--call-frame-id <id>`.

A debugger-paused tab is alive. Tab switching reports `debuggerPaused: true` rather than treating it as a discarded renderer and attempting recovery that could alter state.

### Logpoints

```bash
agent-browser debug logpoint set <script-id> <line> \
  --when "order.ready" \
  --expression "order" \
  --expression "cart.total" \
  --tag phase=checkout \
  --json

agent-browser debug events --since 0 --wait 5000 --json
```

Logpoints use a random per-connection private Runtime binding and always return false from the physical breakpoint condition, so a hit does not pause JavaScript. A false `--when` emits nothing. The page console is not an authoritative channel.

Serialization is bounded by depth, property count, array length, string length, and a 64 KiB payload cap. Cycles, `BigInt`, non-finite numbers, functions, symbols, accessors, throwing getters, proxies, and individual expression failures receive explicit safe representations. A thrown `--when` is reported as `whenError`; a thrown value expression is reported as `evaluationError`.

Binding messages are accepted only when the connection nonce, CDP session, execution context, logical probe ID, and active physical binding ID match the daemon registry. Script identity, location, tags, and owner metadata always come from the registry rather than page data.

### Events and lifecycle

```bash
agent-browser debug events --since <sequence> --wait <milliseconds> --json
agent-browser debug events --clear --json
agent-browser debug disable --resume
```

The per-daemon event ring is capped at 10,000 events and 8 MiB. Use `latestSequence` as the next cursor. `bufferGap` and `droppedThroughSequence` report ring eviction. `transportGap`, `lastTransportGapSequence`, and a `transport-gap` event report CDP listener lag. The aggregate `gap` field is true for either condition.

Navigation, target detach, browser close, and connection replacement invalidate physical bindings and pauses. `--persist` permits same-document HMR rebinding only when session, document generation, execution context, compiled URL, and a resolved runtime owner ID all match. Rebinding never crosses a document or connection generation.

Core agent-browser exposes generic CDP facts. The Divebell extension is responsible for Rstack HMR cycle outcomes and state-preservation verification, plus Module Federation shared-module attribution by consumer, runtime instance, and share scope.

### MCP tools

Start MCP with `agent-browser mcp --tools debug` to expose dedicated typed tools for enable, disable, status, scripts, source read and search, breakpoint set/list/remove, logpoint set/list/remove, pause, resume, steps, stack, frame evaluation, and events. These tools delegate through the canonical CLI parser.

Debugger inspection uses the `debug.inspect` action-policy category. Probe changes and execution control use `debug.control`. Frame evaluation uses `evaluate`. Logpoints and conditional breakpoints require both `debug.control` and `evaluate`; a denial takes precedence over confirmation. Confirmation handling also follows the lock-independent recovery path.

## Console and page errors

```bash
agent-browser console
agent-browser console --json
agent-browser console --clear

agent-browser errors
agent-browser errors --clear
```

Use `console --json` when object previews or raw CDP arguments matter for an automated diagnostic script. Use the default text output when an agent only needs to understand what the page logged.

## JavaScript dialogs

```bash
agent-browser dialog status
agent-browser dialog accept
agent-browser dialog accept "prompt text"
agent-browser dialog dismiss
```

By default, `alert` and `beforeunload` dialogs are automatically accepted so they do not block the agent. `confirm` and `prompt` dialogs still require explicit handling. Use `--no-auto-dialog` or `AGENT_BROWSER_NO_AUTO_DIALOG=1` to disable automatic handling.

When a dialog is pending, command responses include a `warning` field with the dialog type and message so agents can recover with `dialog accept` or `dialog dismiss`.

## DevTools and visual inspection

```bash
agent-browser highlight @e4
agent-browser highlight "#submit"
agent-browser inspect
```

`highlight` draws attention to an element in the live page, which is useful when running headed or when viewing the session through streaming or the dashboard. `inspect` opens Chrome DevTools for the active page through a local proxy while the daemon continues to accept agent-browser commands.

## Chrome trace capture

```bash
agent-browser trace start

agent-browser open https://example.com
agent-browser click @e3

agent-browser trace stop ./trace.json
```

`trace start` begins a Chrome DevTools trace. `trace stop [path]` ends tracing and saves a Chrome Trace Event JSON file. If no path is provided, agent-browser writes an auto-generated trace file under its temp directory.

Use [Profiler](/profiler) when you want curated performance categories and event counts. Use raw traces when you need a general Chrome trace for lower-level debugging.
